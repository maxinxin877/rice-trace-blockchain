# 部署指南（Linux 云服务器 + Docker Compose）

从零把「水稻产品质量安全溯源系统」部署到一台 Linux 云服务器：**MySQL + Redis + 后端（Spring Boot）+ 前端（Nginx）** 四个容器一键启动。

> 前端在镜像内构建，服务器**不需要**安装 Java / Node / MySQL / Nginx，只需要 Docker。

---

## 0. 部署后的样子

```
                    公网只暴露一个端口（默认 80）
                              │
                    ┌─────────▼─────────┐
   浏览器 / 小程序  │  web (Nginx)      │  rice-web
                    │  前端静态资源      │
                    │  /api/ → 反代     │
                    └─────────┬─────────┘
                              │ 容器内网 rice-net
                    ┌─────────▼─────────┐
                    │  app (Spring Boot)│  rice-app   端口 8080（仅本机可访问，调试用）
                    └───┬───────────┬───┘
                ┌───────▼───┐   ┌───▼───────┐
                │ mysql:8.0 │   │ redis:7   │  仅内网可达，不对公网开放
                │ 数据卷持久化│   │ 数据卷持久化│
                └───────────┘   └───────────┘
```

| 服务 | 容器名 | 端口 | 对外 | 说明 |
| --- | --- | --- | --- | --- |
| web | rice-web | 80 | ✅ 公网 | 前端页面 + `/api/` 反向代理 |
| app | rice-app | 8080 | 仅 127.0.0.1 | 后端接口（`/api/v1/...`） |
| mysql | rice-mysql | 3306 | ❌ 仅容器内网 | 首次启动自动执行 `sql/init.sql` |
| redis | rice-redis | 6379 | ❌ 仅容器内网 | 技术栈要求，弱依赖 |

数据持久化（Docker 数据卷）：`mysql-data`、`redis-data`、`upload-data`（上传的照片/证书）。

## 1. 服务器准备

> 需要 **Docker Engine 20.10+ 与 Docker Compose v2**（命令用 `docker compose`，不是老的 `docker-compose`）。
> 本项目 compose 文件未声明 `version:` 字段，v2 会直接识别；若提示 `unsupported Compose file version`，请先升级 Docker。

**建议配置**：2 核 4G 内存、40G 系统盘、Ubuntu 22.04 / Debian 12 / CentOS 7+（x86_64）。
（2G 内存也能跑，但首次构建较吃力，建议先加 2G swap。）

### 1.1 安装 Docker 与 Compose

**Ubuntu / Debian：**

```bash
# 一键安装脚本（官方）
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
# 免 sudo（重新登录后生效）
sudo usermod -aG docker $USER
newgrp docker
# 验证
docker version && docker compose version
```

**CentOS / RHEL / 阿里云 Linux：**

```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
sudo usermod -aG docker $USER && newgrp docker
docker compose version
```

> 若上面脚本拉取慢，用系统包管理器装：`apt install -y docker.io docker-compose-plugin` 或 `yum install -y docker-ce docker-compose-plugin`（需先加官方仓库）。

### 1.2 放行端口

- **云厂商安全组**：放行 `80`（若 `.env` 里改了 `HTTP_PORT`，放行对应端口）。**不要**放行 3306 / 6379。
- **系统防火墙**（如启用 ufw / firewalld）：

```bash
sudo ufw allow 80/tcp && sudo ufw reload        # Ubuntu
sudo firewall-cmd --add-port=80/tcp --permanent && sudo firewall-cmd --reload   # CentOS
```

### 1.3（可选）配置 Docker 镜像加速

国内服务器拉取 `mysql:8.0`、`node:22-alpine` 等基础镜像可能很慢，可配置镜像加速：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com"
  ]
}
EOF
sudo systemctl daemon-reload && sudo systemctl restart docker
```

> 镜像加速地址时效性变化较快，若失效请换成你云厂商提供的加速地址。Maven / npm 依赖已默认使用国内镜像源（见下文 `.env`）。

## 2. 把代码放到服务器

**目录结构必须是这样的**（`docker-compose.yml` 里用 `../front_code` 作为前端构建上下文）：

```
/opt/rice-trace/
├── back_code/          # 后端：Dockerfile、docker-compose.yml、sql/、docker/、src/
└── front_code/         # 前端：Dockerfile、nginx.conf、.env.production、src/
```

### 方式一：Git（如果代码在仓库里）

```bash
sudo mkdir -p /opt/rice-trace && sudo chown -R $USER /opt/rice-trace
cd /opt/rice-trace
git clone <你的仓库地址> .      # 或用 git clone 后把 back_code / front_code 放进来
```

### 方式二：本地上传（scp / WinSCP / 宝塔）

在**本地**执行（Windows 可用 PowerShell 或 WinSCP）：

```bash
scp -r back_code front_code root@<服务器IP>:/opt/rice-trace/
```

> 上传前建议删掉本地的 `front_code/node_modules`、`back_code/target`，能显著加快上传（服务器里会重新安装/构建）。

## 3. 配置环境变量

```bash
cd /opt/rice-trace/back_code
cp .env.example .env
```

编辑 `.env`，**至少要改这两项**：

```bash
MYSQL_ROOT_PASSWORD=<你的数据库强密码>
JWT_SECRET=<至少 48 个字符的随机串>
```

生成随机串：

```bash
openssl rand -base64 24     # 给 MYSQL_ROOT_PASSWORD
openssl rand -base64 48     # 给 JWT_SECRET（HS384 要求 >= 48 字符，太短会启动失败）
```

其余可选项（默认值即可）：`HTTP_PORT`（默认 80）、`JWT_EXPIRE_SECONDS`、`BCOS_ENABLED`、`JAVA_OPTS`、`MAVEN_MIRROR`、`NPM_REGISTRY`。

> `.env` 已被 git 忽略，不会提交；权限建议收紧：`chmod 600 .env`。

## 4. 一键启动

```bash
cd /opt/rice-trace/back_code
docker compose up -d --build
```

建议先做一次配置自检（会校验 compose 语法与变量是否齐全，不启动容器）：

```bash
docker compose config -q && echo "compose 配置校验通过"
```

**首次构建约 5～15 分钟**（下载基础镜像 + Maven 依赖 + npm 依赖），之后再次启动只需几十秒。

观察进度：

```bash
docker compose ps                # 四个服务状态；app 的 STATUS 从 starting → healthy
docker compose logs -f app       # 看到 "Started QukuailianApplication" 即后端就绪
```

`docker compose ps` 正常时应类似：

```
NAME          STATUS
rice-mysql    Up (healthy)
rice-redis    Up (healthy)
rice-app      Up
rice-web      Up
```

## 6. 日常运维

```bash
cd /opt/rice-trace/back_code

docker compose ps                       # 状态
docker compose logs -f app              # 后端日志（Ctrl+C 退出查看）
docker compose logs -f web              # Nginx 访问日志
docker compose restart app              # 重启后端
docker compose down                     # 停止全部（保留数据卷）
docker compose up -d                    # 再次启动
```

### 6.1 更新代码后重新部署

```bash
cd /opt/rice-trace
git pull                                # 或重新上传文件
cd back_code
docker compose up -d --build app web    # 只重建后端与前端
```

### 6.2 备份

```bash
cd /opt/rice-trace/back_code
mkdir -p /opt/backup

# 数据库（--single-transaction 保证一致性，不锁表）
docker compose exec -T mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" \
    --single-transaction --routines --default-character-set=utf8mb4 qukuailian' \
    > /opt/backup/qukuailian_$(date +%F).sql

# 上传的文件（数据卷名 = compose 项目名 + 卷名）
docker run --rm -v rice-trace_upload-data:/data -v /opt/backup:/backup alpine \
    tar czf /backup/upload_$(date +%F).tar.gz -C /data .
```

### 6.3 恢复

```bash
# 数据库
cat /opt/backup/qukuailian_2026-09-10.sql | \
  docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" qukuailian'

# 上传文件
docker run --rm -v rice-trace_upload-data:/data -v /opt/backup:/backup alpine \
    sh -c 'tar xzf /backup/upload_2026-09-10.tar.gz -C /data'
```

### 6.4 彻底重置（清空所有数据后重新初始化）

```bash
docker compose down -v        # ⚠️ 会删除数据卷：数据库、Redis、上传文件全部清空
docker compose up -d --build  # 重新执行 sql/init.sql 建库建表
```

## 7. 安全建议（重要）

1. **修改默认密码**：6 个初始账号密码都是 `123456`，上线前务必修改：
   ```bash
   docker compose exec mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" qukuailian -e \
     "UPDATE user SET password = MD5(CONCAT(salt,'你的新密码')) WHERE username='admin';"
   ```
   （密码算法为 `MD5(salt + 明文)`，与后端 `UserServiceImpl` 一致。）
2. **不要对公网开放 3306 / 6379**：本编排已不暴露这两个端口，安全组也不要放行。
3. **JWT_SECRET 必须换成随机值**，且 `>= 48` 字符。
4. **启用 HTTPS**：`front_code/nginx.conf` 末尾已给出 443 + 证书的示例配置；有域名时推荐用 certbot 申请免费证书，把证书挂载到 `rice-web` 容器：
   ```yaml
   # docker-compose.yml 的 web 服务下追加
   volumes:
     - /etc/letsencrypt/live/your-domain:/etc/nginx/certs:ro
   ```
   同时把 `HTTP_PORT` 保持 80 用于 ACME 校验，并在证书就绪后启用 443 段。
5. **`.env` 权限**：`chmod 600 .env`。
6. 若只是演示/答辩，可忽略 HTTPS，但要保持数据库端口不对外。

## 8. 接入真实 FISCO BCOS 链（可选）

默认 `BCOS_ENABLED=false`：**不连链，上链动作模拟成功**，全流程可跑通，适合演示与答辩。

要接入真实链：

1. 按 `docs/FISCO_BCOS搭建指南.md` 搭链并在控制台 `deploy Evidence` 部署存证合约。
2. 把 SDK 证书放进 `src/main/resources/bcos/conf/`（构建时会拷进镜像 `/app/bcos/conf`），并把 `src/main/resources/bcos/config.toml` 的 `peers` 改成链节点地址。
3. 在 `.env` 中打开开关：

```bash
BCOS_ENABLED=true
BCOS_CONTRACT_ADDRESS=0x你的合约地址
```

4. 重新构建后端：

```bash
cd /opt/rice-trace/back_code
docker compose up -d --build app
```

> 注意事项：链节点若在宿主机，`config.toml` 的 `peers` 填宿主机内网 IP；链的 channel 端口（默认 20200）需能从容器访问。

## 9. 常见问题（FAQ）

| 现象 | 原因与处理 |
| --- | --- |
| 打开页面 **502 Bad Gateway** | 后端还没就绪或启动失败。`docker compose logs -f app` 看报错；首次启动 MySQL 初始化需 20～40 秒，稍等再刷新。 |
| **登录接口报 50001** | 看 `docker compose logs app`：常见是数据库连不上（`.env` 密码与数据卷内不一致，见下一条）。 |
| 改了 `.env` 的 `MYSQL_ROOT_PASSWORD` 后连不上 | 数据卷里仍是**旧密码**。两种处理：① 用旧密码进容器改密码：`docker compose exec mysql mysql -uroot -p旧密码 -e "ALTER USER 'root'@'%' IDENTIFIED BY '新密码';"`；② 演示数据可丢时 `docker compose down -v` 重建。 |
| **`init.sql` 没生效、表不存在** | 初始化脚本只在**数据卷为空**时执行。若之前启动过，需要 `docker compose down -v` 后再 `up`。 |
| 上传图片提示失败（HTTP 413） | Nginx 体积限制。本项目已设 `client_max_body_size 50m`，若自行改过配置需同步调整。 |
| 上传成功但打开照片 404 | 上传目录未持久化或换了目录。本编排已挂载 `upload-data:/app/upload`，且后端按**绝对路径**落盘；不要手动删数据卷。 |
| 中文显示成 `????` 或乱码 | 已统一 `utf8mb4` + `TZ=Asia/Shanghai`；若是自己导入 SQL 造成的，请用 `--default-character-set=utf8mb4` 重新导入。 |
| 时间差 8 小时 | 本编排已设 `TZ=Asia/Shanghai` 与 MySQL `--default-time-zone=+08:00`；若自建 MySQL 需同样设置。 |
| 80 端口被占用 | 改 `.env` 的 `HTTP_PORT=8000`，然后 `docker compose up -d web`，访问 `http://IP:8000/`。 |
| 构建卡在下载依赖 | 检查 `.env` 的 `MAVEN_MIRROR` / `NPM_REGISTRY`；Docker 基础镜像慢则配置 1.3 的镜像加速。 |
| 内存不足（OOM / 构建被杀） | 2G 内存服务器先加 swap：`fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`；或把 `.env` 的 `JAVA_OPTS` 调成 `-XX:MaxRAMPercentage=60`。 |
| 想临时直连后端排查 | 后端已绑定 `127.0.0.1:8080`，在服务器上 `curl http://127.0.0.1:8080/api/v1/...`；远程调试用 SSH 隧道 `ssh -L 8080:127.0.0.1:8080 root@IP`。 |
| 报错找不到 `../front_code/Dockerfile` | 目录结构不对：`front_code` 必须与 `back_code` 同级（见第 2 节），且命令要在 `back_code` 目录下执行。 |
| 前端镜像构建报 `npm ci` 失败 | `package-lock.json` 与 `package.json` 不同步。本地执行 `npm install` 更新 lock 文件后重新上传；或临时把 Dockerfile 里的 `npm ci` 改成 `npm install`。 |
| 安全组已放行 80、服务器上 `curl localhost` 正常，但公网访问不了 | 国内部分云厂商对**未备案域名**访问 80 有限制（服务器本身无故障）。处理：① 用 IP 直接访问通常可行；② 换非 80 端口：`.env` 里设 `HTTP_PORT=8000` 后 `docker compose up -d web`，访问 `http://IP:8000/`（安全组同步放行 8000）；③ 备案域名后再用 80。 |

## 10. 部署相关文件清单

| 文件 | 作用 |
| --- | --- |
| `back_code/docker-compose.yml` | 四个服务的编排（唯一入口） |

| `front_code/.env.production` | 前端生产构建变量（`VITE_API_BASE_URL=/api/v1`） |
