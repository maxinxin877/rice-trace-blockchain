# 前端代码结构说明（front_code）

> 水稻产品质量安全溯源系统 · Web 管理端 + H5 扫码端
> 技术栈：Vue 3.4/3.5（`<script setup>` 语法糖）+ TypeScript + Vite 8 + Element Plus + Pinia + Vue Router（Hash 模式）+ ECharts + Leaflet + Axios

## 四、api —— 接口层

### 4.1 `src/api/request.ts`（核心基础设施）

全站唯一的 Axios 实例与拦截器，是所有页面的数据出入口，**也是前后端字段差异的集中适配点**：

- 实例配置：`baseURL = VITE_API_BASE_URL || '/api/v1'`、`timeout: 15000`、JSON 请求头
- 请求拦截器：
  - 从 `localStorage.token` 取令牌，加 `Authorization: Bearer {token}`
  - **分页参数改名**：前端统一用 `page`，后端要 `pageNo`，在此自动改写（`page` → `pageNo` 并删除 `page`）
- 响应拦截器：
  - `responseType === 'blob'` 的二进制请求直接放行，不做 JSON 归一化
  - **成功码归一化**：后端成功码为 `0`，前端约定 `200`，此处统一
  - **分页结构归一化**：后端返回 `pageNo`，前端补 `page` 与 `totalPages = ceil(total/pageSize)`
  - 业务失败（`code` 非 0/200）统一 `ElMessage.error` 后 reject
  - HTTP 错误分支：401 清 token/role/userName 并跳 `#/login`（用 `window.location.hash.startsWith('#/login')` 防重复跳转）；403/404/500 各有中文提示；无响应提示「网络连接异常」
- 导出方法：`get` / `post` / `put` / `del` / `getBlob`（`getBlob` 专用于需要鉴权的文件下载，用 blob 形式取回原始二进制）

### 4.2 `src/api/modules/` —— 业务接口模块

统一约定：每个模块导出 `xxxApi` 对象；多数模块内部用 `const USE_MOCK = import.meta.env.VITE_USE_MOCK === 'true'` 做 **Mock/真实双实现**，两者函数签名完全一致，调用方（页面）无感知。

| 文件 | 负责的业务 | 关键接口（`baseURL` 已含 `/api/v1`） |
|---|---|---|
| `auth.ts` | 认证 | `POST /auth/login`、`POST /auth/register`、`GET /auth/me`、`POST /auth/logout`。**该模块没有 Mock 分支**，必须连后端；同时导出 `LoginParams`/`LoginUser`/`LoginResult` 类型 |
| `field.ts` | 地块档案 | `GET/POST /rice/fields`、`GET/PUT /rice/fields/{fieldId}`、`POST /rice/fields/{fieldId}/photos`（绑定照片，body 带 `reason` 留审计痕迹） |
| `plantingBatch.ts` | 种植批次 | `GET/POST /rice/planting-batches`、`GET/PUT /rice/planting-batches/{batchId}` |
| `farmingLog.ts` | 农事记录 | `GET/POST /rice/planting-batches/{plantingBatchId}/farming-logs`。**嵌套资源路径**；查询参数 `operationTimeStart/End` 会改名为后端要求的 `startTime/endTime`；后端无「跨批次全量列表」，缺 `plantingBatchId` 时直接返回空分页、不发请求 |
| `environmentRecord.ts` | 环境数据 | `GET/POST /rice/planting-batches/{plantingBatchId}/environment-records`，同样是嵌套路径 + 时间参数改名；该模块的 CreateDTO 就地定义在本文件内 |
| `storageReceipt.ts` | 收储入库单 | `GET /rice/storage-receipts`、`GET /rice/storage-receipts/{id}`、`POST /rice/storage-receipts` |
| `millingBatch.ts` | 碾米加工批次 | `GET /rice/milling-batches`、`GET /rice/milling-batches/{id}`、`POST /rice/milling-batches`、`PUT /rice/milling-batches/{id}/complete`（完成加工） |
| `productBatch.ts` | 成品批次 | `GET/POST /rice/product-batches`、`GET /rice/product-batches/{id}/trace`（返回全链路 `TraceResult`） |
| `qualityTest.ts` | 质检单 | `POST /rice/storage-receipts/{businessId}/quality-tests`。**字段改名适配**：前端 `items[].itemValue` → 后端 `testItems[].value`。只有新增，没有列表/删除接口 |
| `traceability.ts` | 溯源核心（489 行，最大的模块） | 防伪码 `GET /rice/trace-codes`、`POST /rice/trace-codes/generate`、`POST /rice/trace-codes/activate`；窜货 `GET /rice/channel-warnings`；小程序端 `GET /mini/rice/trace/{code}`、`POST /mini/rice/trace/{code}/verify`、`GET/POST /mini/rice/trace/{code}/chain-proof`；链上存证 `GET /rice/chain-proofs`、`GET/POST /rice/chain-proofs/{businessType}/{businessId}(/verify)`。**体积大的原因**：内含三套后端原始 DTO 的类型声明 + 四个适配转换函数（`mapTraceDetail`/`mapVerifyResult`/`mapMiniChainProof`/`mapChainProofRecord`），把后端多段式原始结构组装成前端时间轴视图模型，并把验真结果推导为「正品/重复扫码/窜货/假冒」四态 |
| `regulation.ts` | 监管审计 | `POST /rice/regulation/yield-balance/check`、`GET /rice/regulation/yield-balance/results`、`GET /rice/regulation/risk-warnings`、`PUT /rice/regulation/risk-warnings/{id}/handle`、`GET /rice/regulation/audit-logs` |
| `dashboard.ts` | 数据看板 | `GET /rice/regulation/dashboard/summary`（注意看板接口挂在 regulation 命名空间下） |
| `file.ts` | 文件 | `GET /files/{fileId}/download`（经 `getBlob` 取回后 `URL.createObjectURL` 给 `<img>` 用，因为下载接口需鉴权，直接写 `src` 会 401）、`GET /files/{fileId}`（元数据，含 `sha256`） |

### 4.3 `src/api/mock/` —— Mock 体系

| 文件 | 作用 |
|---|---|
| `index.ts` | 三个 Mock 工具：`mockDelay(ms)` 模拟网络延迟、`mockPaginate(list, page, pageSize)` 产出与后端一致的分页结构、`mockId(prefix)` 生成 `前缀+日期+4位随机` 的业务主键 |
| `imageCache.ts` | 仅 6 行：一个 `Map<fileId, base64>`，Mock 模式下把上传的图片以 dataURL 存在内存里供跨页面展示。**当前只有写入方（FileUpload）没有读取方**，属预留未闭环 |
| `data/*.ts`（11 个） | 各业务域的 Mock 常量数组：`fields`、`plantingBatches`、`farmingLogs`、`environmentRecords`、`storageReceipts`、`millingBatches`、`productBatches`、`qualityTests`、`traceability`、`regulation`、`dashboard`。**数据主键互相咬合**（`FIELD202607010001 → RPB202607010001 → SREC202607010001 → MB202607010001 → PROD20260701001 → RC20260718000001`），可完整走通「地块→种植→入库→加工→成品→防伪码→扫码」全链路；`traceability.ts` 覆盖防伪码四态、跨区域扫码预警，以及一条 `currentHash ≠ chainHash` 的存证用于演示核验失败 |

**Mock 开关机制**：没有使用 `vite-plugin-mock`/MSW 之类的中间件，而是「环境变量 + 模块内分支」：

- 开关值来自 `VITE_USE_MOCK`（Vite 在构建期做静态替换）
- 落地写法有两种并存：**导出期三元**（`getList: USE_MOCK ? mockGetList : realGetList`，便于打包摇树）用于 field/plantingBatch/farmingLog/environmentRecord/storageReceipt/millingBatch/productBatch/qualityTest；**调用期 if 早返回**（`if (!USE_MOCK) return (await get(...)).data`）用于 traceability/regulation/dashboard
- Mock 数据是模块级单例数组，新增数据在本会话内可见、刷新还原

## 七、layouts / router / stores

| 文件 | 作用 |
|---|---|
| `layouts/MainLayout.vue` | 管理端主框架：可折叠侧边栏（绿色主题、分组菜单、图标由全局注册的图标组件动态渲染）+ 顶部栏（折叠按钮、面包屑、当前用户名与角色标签、退出登录）+ `el-main` 内容区。菜单由内置的 `allMenuItems` 配置 + `isVisibleForRole()` **按当前角色过滤**，`onMounted` 调 `userStore.fetchMe()` 用后端数据校正本地登录态 |
| `router/index.ts` | 路由表与守卫。路由用 `createWebHashHistory`（Hash 模式）；`riceRoutes` 覆盖 18 条业务路由 + 1 条 `redirect`，扫码端 4 条路由标记 `meta.public`（免登录）。通过 `declare module 'vue-router'` 扩展了 `RouteMeta`（`title/icon/hidden/public/roles`）。**导航守卫逻辑**：公开路由直接放行 → 登录页在已登录时跳看板 → 未登录先 `initFromStorage()` 恢复再决定是否跳登录 → 最后校验 `meta.roles` 与当前角色是否匹配，不匹配退回看板 |
| `stores/user.ts` | 用户状态（Pinia）。维护 `token/userName/role/permissions`，定义 6 个前端角色（`RICE_ADMIN/FARMER/WAREHOUSE/FACTORY/BRAND/REGULATOR`）与「后端角色名 → 前端角色名」映射（`WAREHOUSE_KEEPER→WAREHOUSE`、`PROCESSING_FACTORY→FACTORY`、`BRAND_OPERATOR→BRAND`）；内置 `ROLE_PERMISSIONS` 角色-权限码表（权限码与后端 JWT 中的 `permissions` 完全一致）。提供 `login`（成功后写 localStorage）、`logout`（先清本地再异步通知后端）、`fetchMe`、`initFromStorage` |
| `stores/app.ts` | 界面状态。只管理侧边栏折叠状态 `sidebarCollapsed` 与切换方法 |

**权限体系说明（容易被问到）**：真正的接口鉴权在后端——`AuthInterceptor` 校验 `Authorization` 头并把 JWT 里的 `permissions` 写入上下文，再按 Controller 方法上的 `@RequirePermission("权限码")` 注解拦截。前端这一侧：**路由与菜单用的是角色（`meta.roles`）判断**，`ROLE_PERMISSIONS`/`hasPermission`/`usePermission` 这套权限码机制已实现但尚未被页面接入（登录响应的 `user` 对象只返回 `role`，不含权限数组）。
