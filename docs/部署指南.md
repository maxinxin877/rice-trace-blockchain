# 部署指南

本文档覆盖三种部署方式：**开发环境手动部署**、**生产环境手动 + Nginx**、**Docker Compose 一键部署**。

---

## 环境要求

| 依赖 | 版本 | 说明 |
|---|---|---|
| JDK | 21+ | 后端运行时 |
| Maven | 3.9+ | 后端构建（或使用项目自带 mvnw） |
| MySQL | 8.0+ | 数据库 |
| Node.js | 20+ | 前端构建与开发 |
| npm | 10+ | 前端包管理 |
| Docker | 24+ | 仅 Docker Compose 方式需要 |
| Docker Compose | v2 | 仅 Docker Compose 方式需要 |

> Redis 在开发环境下已通过 `application-dev.yml` 排除自动配置，无需单独启动。

## 一、开发环境部署（推荐）

前后端分别以开发模式启动，Vite 内置代理转发 API 请求到后端。

### 1.1 初始化数据库

```powershell
# 启动 MySQL 服务
Start-Service MySQL80

# 执行初始化脚本（创建库 qukuailian + 18 张表 + 6 个种子账号）
Get-Content -Raw "back_code/sql/init.sql" | mysql -uroot -p123456
```

> 如果 MySQL root 密码不是 `123456`，请修改 `back_code/src/main/resources/application-dev.yml` 中的 `spring.datasource.password`。

### 1.2 启动后端（终端 1）

```powershell
cd back_code

# 首次运行：Maven 自动下载依赖（约 1-3 分钟）
.\mvnw.cmd spring-boot:run
```

启动成功标志：

```
Tomcat started on port(s): 8080 (http) with context path '/api/v1'
Started QuukuailianApplication in X.XX seconds
```

后端常驻运行，**不要关闭此终端**。

### 1.3 启动前端（终端 2）

```powershell
cd front_code

# 安装依赖
npm install

# 确认 .env.local 配置（VITE_USE_MOCK=false 对接真实后端）
# 如果 .env.local 不存在，复制 .env.development 并修改：
#   VITE_USE_MOCK=false
#   VITE_API_BASE_URL=/api/v1

npm run dev
```

启动成功标志：

```
➜  Local:   http://localhost:3000/
```

### 1.4 验证

浏览器打开 **http://localhost:3000**，使用种子账号登录：

| 账号 | 密码 | 角色 |
|---|---|---|
| `admin` | `123456` | 系统管理员 |
| `farmer1` | `123456` | 种植户 |
| `keeper1` | `123456` | 仓储员 |
| `factory1` | `123456` | 加工员 |
| `brand1` | `123456` | 品牌运营 |
| `regulator1` | `123456` | 监管人员 |

### 1.5 服务调用链

```
浏览器 http://localhost:3000
    │  axios 请求 /api/v1/xxx
    ▼
Vite Dev Server (port 3000)
    │  proxy /api → http://localhost:8080
    ▼
Spring Boot (port 8080, context-path /api/v1)
    │  MyBatis-Plus
    ▼
MySQL (port 3306, 库名 qukuailian)
```

### 1.6 纯 Mock 模式（仅前端演示）

不想启动后端？删除或重命名 `front_code/.env.local`，前端会自动启用 Mock 数据：

```powershell
cd front_code
# 删除 .env.local 后直接启动
npm run dev
```

## 二、生产环境部署（手动 + Nginx）

### 2.1 构建前端产物

```powershell
cd front_code

# 确保生产环境配置正确
# .env.production 中 VITE_API_BASE_URL=/api/v1（通过 Nginx 反代）
npm run build

# 产物目录
# front_code/dist/
```

### 2.2 构建后端 Jar

```powershell
cd back_code

.\mvnw.cmd clean package -DskipTests

# 产物
# back_code/target/qukuailian-0.0.1-SNAPSHOT.jar
```

### 2.3 Nginx 配置

```nginx
server {
    listen 80;
    server_name rice.example.com;

    # 前端静态资源
    root /var/www/front_code/dist;
    index index.html;

    # 前端路由 history 模式回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 反向代理
    # 前端请求 /api/v1/xxx → 后端 http://127.0.0.1:8080/api/v1/xxx
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 10s;
        proxy_read_timeout 30s;
    }

    # 静态资源缓存（js/css/图片等）
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|ico|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public";
    }
}
```

> **注意**：`proxy_pass` 不要带尾部 `/`，这样 `/api/v1/xxx` 会原样传递到后端（后端 context-path 就是 `/api/v1`）。

### 2.4 启动后端

```bash
# 上传 jar 到服务器后
nohup java -jar qukuailian-0.0.1-SNAPSHOT.jar \
  --spring.profiles.active=dev \
  > app.log 2>&1 &

# 或者指定生产环境配置（建议新建 application-prod.yml）
nohup java -jar qukuailian-0.0.1-SNAPSHOT.jar \
  --spring.profiles.active=prod \
  --spring.datasource.password=YourStrongPassword \
  > app.log 2>&1 &
```

### 2.5 一键部署脚本（Linux 示例）

```bash
#!/bin/bash
# deploy.sh

APP_DIR=/opt/rice-trace
FRONT_DIST=./front_code/dist
BACK_JAR=./back_code/target/qukuailian-0.0.1-SNAPSHOT.jar

# 构建
(cd front_code && npm install && npm run build)
(cd back_code && ./mvnw.cmd clean package -DskipTests)

# 部署前端
rm -rf $APP_DIR/front
cp -r $FRONT_DIST $APP_DIR/front

# 部署后端
cp $BACK_JAR $APP_DIR/app.jar

# 重启后端
pkill -f 'java.*qukuailian' 2>/dev/null
cd $APP_DIR
nohup java -jar app.jar > app.log 2>&1 &

echo "部署完成，访问 http://rice.example.com"
```

## 三、Docker Compose 一键部署

> Dockerfile、docker-compose.yml、nginx.conf 均位于 `back_code/` 目录下。

### 3.1 前置条件：构建前端

Docker Compose 的 Nginx 需要前端构建产物，请先执行：

```powershell
cd front_code
npm install
npm run build

# 把 dist 复制到后端目录下的 frontend/dist
New-Item -ItemType Directory -Force -Path ..\back_code\frontend
Copy-Item -Recurse -Force .\dist ..\back_code\frontend\dist
```

项目目录最终如下（从 `back_code/` 视角）：

```
back_code/
├── Dockerfile
├── docker-compose.yml
├── nginx/nginx.conf
├── sql/init.sql                    # 首次启动自动建库
├── frontend/dist/                  # 前端构建产物（上一步生成）
└── target/qukuailian-0.0.1-SNAPSHOT.jar  # 可选，Dockerfile 会自己构建
```

### 3.2 启动

```powershell
cd back_code

# 一键启动（MySQL + 后端 + Redis + Nginx）
docker compose up -d --build
```

启动后各服务地址：

| 服务 | 地址 | 说明 |
|---|---|---|
| Nginx（前端 + API 反代） | http://localhost:80 | 统一入口 |
| 后端 API（直连调试） | http://localhost:8080/api/v1 | 跳过 Nginx |
| MySQL | localhost:3306 | root / root123456 |
| Redis | localhost:6379 | 无密码 |

### 3.3 常用命令

```powershell
docker compose ps                    # 查看服务状态
docker compose logs -f app           # 跟踪后端日志
docker compose logs -f nginx         # 跟踪 Nginx 日志
docker compose restart app            # 重启后端（改代码后重新构建：up -d --build）
docker compose down                  # 停止（保留数据卷）
docker compose down -v               # 停止并清空数据卷（MySQL 会重新执行 init.sql）
```

### 3.4 docker-compose.yml 配置项

后端 `app` 服务通过环境变量覆盖 Spring Boot 配置：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `SPRING_DATASOURCE_URL` | `jdbc:mysql://mysql:3306/qukuailian?...` | MySQL 连接串 |
| `SPRING_DATASOURCE_USERNAME` | `root` | MySQL 用户名 |
| `SPRING_DATASOURCE_PASSWORD` | `root123456` | MySQL 密码 |
| `SPRING_DATA_REDIS_HOST` | `redis` | Redis 主机 |
| `BCOS_ENABLED` | `false` | FISCO BCOS 开关 |
| `BCOS_CONTRACT_ADDRESS` | 空 | 合约地址 |

## 四、FISCO BCOS 可选接入

默认 `bcos.enabled=false`，区块链上链动作会模拟成功，开发演示无需搭建。

接入真实链的步骤：

1. 按 [FISCO_BCOS搭建指南](FISCO_BCOS搭建指南.md) 搭链并部署 `Evidence` 存证合约
2. 把 SDK 证书和 `config.toml` 放到 `back_code/src/main/resources/bcos/` 下
3. 修改配置（两种方式任选其一）：
   - **开发模式**：编辑 `application.yml` 或 `application-dev.yml`
     ```yaml
     bcos:
       enabled: true
       contract-address: "0x2c5b1f0f0c1a5f8e6b7c..."
     ```
   - **Docker 模式**：修改 `docker-compose.yml` 中 `app` 服务的环境变量
     ```yaml
     BCOS_ENABLED: "true"
     BCOS_CONTRACT_ADDRESS: "0x2c5b1f0f0c1a5f8e6b7c..."
     ```
4. 重启后端

> 注意：SDK 需要访问链节点的 `20200` channel 端口。节点在宿主机时 `config.toml` 的 `peers` 填宿主机 IP；节点也在容器时需加入同一 Docker 网络。

## 五、常见问题

| 问题 | 原因 | 解决 |
|---|---|---|
| MySQL 初始化脚本没生效 | `init.sql` 只在数据卷首次创建时执行 | `docker compose down -v` 清空数据卷后重新启动 |
| 改代码后后端没更新 | Docker 镜像没有重新构建 | `docker compose up -d --build` |
| CORS 跨域报错 | 前端和后端不同源 | 生产环境走 Nginx 同源反代；开发环境后端已放开跨域，检查 `VITE_API_BASE_URL` 是否以 `/api/v1` 开头 |
| 前端页面空白（Docker） | Nginx 找不到前端产物 | 确认 `back_code/frontend/dist/` 目录存在且有 `index.html` |
| 端口被占用 | 80/8080/3306 已被其他进程使用 | 修改 `docker-compose.yml` 的 `ports` 映射，或 `netstat -ano \| findstr :8080` 找到占用进程并结束 |
| Redis 连接失败（开发模式） | dev 环境已排除 Redis 自动配置 | 忽略此问题，开发模式无需 Redis；Docker 模式 Redis 会自动启动 |
| `LocalDateTime.parse(null)` 报错 | 后端旧版本 Bug | 确保使用最新代码，已在 ServiceImpl 中修复日期参数空值处理 |
| VS Code 报 tsconfig 错误 | TypeScript 服务未刷新 | `Ctrl+Shift+P` → `TypeScript: Restart TS Server`，或 `Developer: Reload Window` |
| Docker build 拉镜像慢 | 国内网络 | 配置 Docker 镜像加速器（如阿里云），或使用本地 Maven 仓库 |
