# 前端联调演示脚本

## 1. 演示目标

演示防伪码、产量平衡、风险预警、审计日志和数据看板五个页面已经统一通过 API 模块取数；开发环境可使用 Mock，生产环境切换到 `/api/v1` 后端接口。

## 2. 环境准备

```powershell
cd front_code
npm install
npm run dev -- --host 127.0.0.1 --port 4173
```

- 开发演示：`.env.development` 中 `VITE_USE_MOCK=true`。
- 后端联调：将当前运行环境设置为 `VITE_USE_MOCK=false`，接口前缀保持 `VITE_API_BASE_URL=/api/v1`。
- 管理员账号：`admin1 / 123123123`。
- 品牌账号：`admin5 / 123123123`。
- 监管账号：`admin6 / 123123123`。

## 3. 推荐演示顺序

### 3.1 数据看板

1. 使用 `admin1` 登录并进入“数据看板”。
2. 说明统计卡来自 `GET /rice/dashboard/summary`。
3. 展示 ECharts 的业务资产柱状图、链上成功率仪表盘、防伪码风险饼图、扫码转化柱状图。
4. 核对统一数据：5 个地块、5 个种植批次、271.5 吨入库原粮、4 个成品批次、5 个防伪码、47 次扫码、4 条风险预警、66.7% 上链成功率。

### 3.2 防伪码管理

1. 进入“监管与风控 → 防伪码管理”。
2. 查询 `RC20260718000001`，验证列表来自 `GET /rice/trace-codes`。
3. 点击“扫码预览”，展示消费者溯源页。
4. 对 `RC20260722000004` 执行激活，验证 `POST /rice/trace-codes/activate`。
5. 点击“批量生成”，选择 `PROD20260701001`，填写数量和包装规格，验证 `POST /rice/trace-codes/generate`。
6. 对有扫码次数的记录点击“扫码记录”。

### 3.3 产量平衡

1. 使用 `admin6` 登录并进入“产量平衡”。
2. 点击“执行校验”，验证 `POST /rice/regulation/yield-balance/check`。
3. 页面自动刷新 `GET /rice/regulation/yield-balance/results` 的记录。
4. 说明校验异常会关联生成风险预警和审计日志。

### 3.4 风险预警

1. 进入“风险预警”，按业务 ID 查询 `RC20260718000002`。
2. 点击“处理”，填写处理结果和处理原因。
3. 提交后验证 `PUT /rice/regulation/risk-warnings/{warningId}/handle`。
4. 返回列表确认状态变为“已处理”，同时进入审计日志确认新增 `HANDLE` 记录。

### 3.5 审计日志

1. 进入“审计日志”。
2. 按业务类型、业务 ID、操作人 ID 或操作类型筛选。
3. 点击详情查看前后哈希、原因、IP 和交易 ID。
4. 说明查询来自 `GET /rice/regulation/audit-logs`。

## 4. 联调验收检查

- 浏览器 Network 中五页请求均使用 `/api/v1/rice/**`。
- 分页参数由前端 `page` 转换为后端 `pageNo`。
- 统一响应同时兼容成功码 `0` 和 `200`。
- 防伪码、成品批次、风险预警、审计日志中的业务 ID 可以互相对应。
- 所有演示业务时间不晚于 2026 年 7 月 26 日。
- `npm run build` 必须通过。
